# OMP GUI

Rust / gpui-kit 0.8.1 的 Windows 原生 OMP 客户端。对话与选区评论沿用第三版基线；支持会话查找、文件引用、设置命令跳转及独立文件／变更标签页。

## 运行

运行打包的 `omp-gui.exe` 需要 Windows、本机 OMP 和 Git。源码构建另需 Rust MSVC 工具链及 Visual Studio C++ Build Tools。

```powershell
cargo run
cargo run -- --project D:\dev\your-project
cargo run -- --demo
cargo run -- --probe
```

鼠标悬停在「项目」标题时显示添加目录的 +；悬停在具体项目行时显示新建会话的 +。新会话直接修改项目目录，不创建 Git 工作树或分支，也不要求已有 Git 提交。Git 仅用于有仓库时的差异读取。

旧版已经建立的工作树会话保留原执行位置和历史数据，不自动移动或删除代码。需要直接在项目目录执行时，点击项目右侧 + 创建新会话。

## 操作

- `Ctrl+Enter` 发送任务与待发送评论。
- `Ctrl+F` 查找激活标签页中的消息、文件正文或差异代码，显示匹配计数和高亮；`Enter` / `Shift+Enter` 循环跳转，`Esc` 关闭。命中折叠的中间回复时自动展开过程记录。
- 输入 `@` 选择当前会话目录中的文件，使用原生引用标签插入；中文和空格文件名自动加引号，发送后由 OMP 自动读取。输入开头的 `/` 展示 OMP 实际提供的命令和技能；`↑↓` 选择、`Tab` / `Enter` 确认、`Esc` 关闭候选；配置类命令确认后直接跳转设置，其余命令插入后用 `Ctrl+Enter` 执行。
- 输入框模型菜单按已配置供应商分组，展示 OMP 当前返回的全部可用模型并标记当前选择；模型切换后重新读取原生推理档位。DeepSeek 使用 `off / low / high / max`，另提供会话级 `auto` 自动选择；不会把通用的 `xhigh` 强加给不支持它的模型。
- 自由选中 AI 回复文字或 Diff 代码，再点击「评论」。Diff 也支持从行号选择代码行。
- `Ctrl+Shift+B` 展开／收起工作面板；`Ctrl+N` 在当前项目目录创建会话；`Ctrl+O` 添加项目。
- 工作面板提供平铺的变更文件列表、文件目录树、结构化 Todo 和子智能体，默认收起。修改／重命名文件为鹅黄色，新增为绿色，删除为红色；行高、图标和间距与文件页统一。文件名优先使用剩余宽度，目录路径最多占四成；宽度不足才截断，选中高亮和点击区域覆盖整行。目录以连续竖线显示层级，点击目录行展开／收起。
- 文件和变更在中央独立标签页中打开，可同时保留多个。会话标签固定在最左侧且不能关闭；其他标签可点 × 关闭。文件标签不显示图标；变更标签使用分支图标及鹅黄色文件名，不加变更文字后缀。切换或收起工作面板不关闭文档。
- 文件树、变更列表和当前文件内容监听磁盘变化自动更新，无需手动刷新；保留目录展开状态、选中项和阅读位置。历史评论引用保持当时版本。
- 无参数的 `/model`／`/models`／`/switch`、`/effort`、`/mcp`、`/lsp`、`/skills`、`/plugins`、`/settings` 等命令跳转到对应设置页，`/advisor configure` 跳转到顾问配置。`/effort high` 等带明确参数的命令仍由 OMP 执行。
- 评论发送后保留引用、意见及关联回应。继续跟进以追加方式记录；只有用户明确操作才标为已解决。
- 「查看当时变更」打开不可变快照；「打开当前代码」读取执行目录的最新文件，不自动猜测评论的新位置。
- 会话右键可归档、取消归档和删除；删除前显示确认，移除 GUI 消息、评论及快照，保留项目文件和 OMP 独立保存的原生记录。
- 「已归档会话」切换归档列表；两侧面板边缘支持拖动，宽度在重启后保留。
- 人与模型的消息悬停时，在段落右下角固定显示本地日期和时间。
- 正在进行的思考流式展开，块完成后收起；工具调用与中间工作说明默认折叠，最终总结保留展开。历史评论定位会展开对应原文。
- 归档列表不提供新增入口；设置中的项目范围显示当前会话项目名，没有当前项目时禁用。
- 不提供 IDE 路径设置或跳转 IDE 按钮。

## OMP 设置

设置页读取本机 `omp config path` 和 `omp config list --json`，动态获取配置目录、类型和说明；全局与项目的显式值从各自 YAML 读取，不依赖不受支持的 `config list --scope`。无需在 GUI 中穷举每个新增设置。支持搜索和重置当前范围。布尔项直接显示 Switch，枚举项使用 Select；允许值从 OMP 自带的文本输出读取。列表虚拟化，配置后台并行读取并缓存，导航不等待加载。

| 分类 | 当前能力 |
| --- | --- |
| 模型 | 图形化服务选择、地址／认证／API 格式表单；获取服务模型、添加／编辑／移除模型及上下文和输出参数；保留未覆盖的高级字段 |
| 网络搜索 | 图形化服务选择、API 密钥注册、SearXNG 地址及 Token、备用服务排序、搜索启停；凭据通过 OMP 原生 auth import 管道保存 |
| 角色与提示词 | modelRoles 映射与自定义角色；新建／编辑 agents/*.md；SYSTEM.md、APPEND_SYSTEM.md 编辑 |
| 工具调用 | OMP 当前注册的工具开关、调用行为和策略设置 |
| LSP / MCP | 原生服务器配置编辑器，以及当前注册的相关设置 |
| 技能 | 原生技能新建、提示词编辑、技能开关／忽略列表／额外目录配置 |
| 插件 | 调用本机 `omp plugin` 列表、安装、启用、停用、卸载；支持全局与项目 --local 范围 |
| 更多设置 | 本机 OMP 注册表中的其他条目，可搜索发现 |

提供商注册文件 `models.yml` 仅开放原生支持的全局范围。项目配置以当前会话执行目录的 `.omp` 目录为准，界面显示实际执行目录；直接目录会话的项目设置写入映射目录；旧工作树会话仍写入其原执行目录。全局设置调用 OMP 原生命令保存，项目 YAML 按字段修改并保留其他字段与注释。

模型和网络搜索使用图形化表单；LSP/MCP 的高级服务器配置保留内置 YAML/JSON 编辑器，其他数组和映射使用 JSON 编辑。它们提供格式校验，最终字段含义和运行时校验由本机 OMP 决定。模型 `apiKey` 建议引用环境变量名称。OAuth、其他服务认证、Skillshare／市场高级操作以及 GUI 未覆盖的设置，可在对应目录的 OMP 终端继续配置，界面中有持续提示。

设置遵循 OMP 自身优先级，环境变量和启动参数可能覆盖保存值。文件编辑器检测外部修改后会拒绝覆盖，需重新读取。配置备份与锁保存在应用数据目录的 `config-backups`，不加入项目变更列表。普通设置后台保存，由 OMP 自身热加载；模型注册保存后空闲会话重新连接，正在运行的任务不被强制中断。角色模型路由和子智能体系统提示词分别按 OMP 原生机制保存。

## 本地数据与边界

默认数据目录为 `%LOCALAPPDATA%\OMP GUI`，支持 `--data-dir <目录>` 或 `OMP_GUI_DATA_DIR`。演示数据放在独立 `demo` 子目录。一个数据目录同时只有一个可写窗口。

- `workspace.json`：项目映射、会话、消息、评论、草稿和历史快照，采用顺序写入及原子替换。
- `worktrees/<会话 ID>`：GUI 创建的工作树；`omp-sessions/<会话 ID>` 保存 OMP 原生会话。
- 文本引用保存 UTF-8 范围和摘要；Diff 行选区保存快照内的前／后版本行范围。字符选区若无法唯一映射，保留原文与完整快照，不猜测重复片段的位置。
- Windows 换行仅在生成展示用 diff 时归一化；快照仍保留读入的原始正文。
- 同一时间运行一个会话；运行期间不切换会话。关闭窗口会结束所管理的 OMP 进程。
- 代码预览仅限 UTF-8、单文件 2 MB；文件通过原生虚拟化 Tree 按目录展开与收起，后台枚举最多 5000 项。完整 IDE 审查和工程编辑不属于本项目范围。
- 文件编辑区的行号栏与正文背景保持同色，深浅主题切换时同步更新。
- 会话中的 LaTeX 公式暂显示原文；当前 gpui-kit 0.8.1 提供公式解析扩展接口，没有内置公式排版控件。
- 敏感交互认证由 OMP 终端完成；GUI 不自行批准工具授权。

## 代码结构与参考

代码分为 `domain`（数据与规则）、`infrastructure`（OMP、文件、配置和持久化）和 `desktop`（原生窗口与交互）。主工作区按输入、会话、文档、查找、运行连接和视图组织；本机 OMP 集成测试独立放在 `tests/omp/`，单元测试靠近实现。详见 [组件职责与维护约定](docs/architecture.md)。界面不使用 WebView。

协议与配置依据 [OMP 官方文档](https://github.com/can1357/oh-my-pi/tree/main/docs)；原生组件依据 [gpui-kit](https://github.com/longbridge/gpui-kit)。

## v0.6.0 队列与会话修复

- 输出期间的追加默认进入 OMP `followUp` 队列，等待本轮完成。等待项右侧的「指示」将该项提升到原生 steering 队列，接收和中断时机由 OMP 决定；不强制 abort。
- 指令真正被接收前只显示在等待区域，不提前切断会话中的当前工作过程。排队指令执行顺序变化时，历史按实际接收顺序记录。重启时未确认执行的排队输入恢复为草稿，并标注状态未确认。
- 点击项目 + 后未输入内容就切换会话，不保存空的「新建会话」；已有草稿、评论和历史会保留。
- 按 Windows 目录实际身份归一化普通路径、大小写及 `\\?\` 路径，合并同目录项目入口并保留会话；不同位置的同名目录不合并。
- read 工具收到开始事件即显示「正在读取」和 Spinner，结束后显示读取记录，始终不可展开；状态栏也不再残留上一次 read 的执行提示。
- 右下角显示上下文百分比及当前模型的窗口上限，悬停可查看精确 token 数。
- 项目列表、会话、设置、注册表单、工作面板及其他可滚动区域使用 gpui-kit 原生滚动条，滚动或悬停右边缘时显示。
- 29 项离线测试通过；真实 DeepSeek 集成测试验证了 followUp 保持排队及提升为 steering。窗口验证覆盖项目合并、空白会话、滚动条、执行中的 read、当前模型窗口上限和右侧「指示」按钮。
