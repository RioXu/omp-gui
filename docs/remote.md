# 连接远程 Linux OMP

[返回 README](../README.md) · [使用说明](usage.md) · [构建与验证](testing.md)

Windows 上保留原生 GUI，OMP、原生会话、项目文件、Git 和配置均在 Linux 上操作。客户端通过 SSH 与 `omp-gui-remote` 通信，不开放 TCP 服务端口，也不建立整份项目的本地副本。

## 首次连接

1. 在终端确认 `ssh 你的Host别名` 可用，完成首次主机身份确认，并配置密钥／SSH Agent。GUI 使用同一 OpenSSH 配置，不提供密码或主机密钥确认窗口。
2. 点击左侧 OMP 标题下的环境菜单，选择新增 SSH 连接。Host 可填 SSH 配置别名或 `user@host`；端口、跳板等放在 SSH 配置中。
3. OMP 路径留空时，从远端用户 shell 环境的 PATH 查找；可填写绝对路径覆盖。profile 留空使用远端默认配置，也可填写 `PI_CODING_AGENT_DIR` 的绝对路径。服务路径通常留空自动部署。
4. 连接后悬停“项目”标题点击 +，在组件目录选择器中选择远端目录。输入 POSIX 绝对路径、点击文件夹逐级进入或返回上级，然后确认。

本地模式也使用同一选择器；没有默认项目目录设置。远端选择器首次从 HOME 开始浏览，HOME 只是浏览起点。

环境按稳定 ID 隔离项目、会话和草稿。修改显示名或 OMP 路径保留原归属；修改 Host 或 profile 会新增一个独立环境，保留旧环境及其历史。SSH 配置别名所指目标应保持稳定。切换环境前仍检查未保存的文件，其他环境正在运行的会话继续处理。

## 自动部署与依赖

服务安装到 `~/.local/share/omp-gui/remote/<GUI版本>/omp-gui-remote`。连接时校验服务版本和协议；不匹配时安装当前版本。安装文件先暂存，校验 SHA-256 后原子替换，权限设为仅当前用户可执行。

优先使用 GUI 旁的 `remote/linux-x86_64/omp-gui-remote` 或 `remote/linux-aarch64/omp-gui-remote`；也可通过本机 `OMP_GUI_REMOTE_BINARY` 指定受信任的服务文件。缺少预编译文件时，GUI 上传内置共享核心／服务源码和锁文件，在远端以 Cargo 构建。该回退需要远端 Rust、Cargo、tar、sha256sum，以及首次获取依赖的网络或已有 Cargo 缓存；不上传 GUI 工作区、聊天数据或本机凭据。构建缓存位于 `~/.cache/omp-gui/`。

手动部署可在 Linux 上执行：

```sh
cargo build --locked --release -p omp-gui-remote
./target/release/omp-gui-remote --version
```

然后在连接设置中填写该二进制的远端绝对路径，或 `~/` 开头的服务路径。高级环境变量 `OMP_GUI_REMOTE_HELPER` 也可覆盖自动服务路径。预编译文件必须匹配 Linux 架构、系统运行库和 GUI 协议；Windows 桌面程序与远端服务是不同构建产物。

服务通过用户的 shell 环境启动，保留模型所需环境变量；shell 启动信息转到 stderr，协议独占 stdout。不会修改 shell 配置、关闭主机身份校验或自动复制本机认证信息。

## 会话、文件与配置

原生会话与该 Linux profile 的 OMP TUI 共用存储。GUI 创建、标题、历史和删除均反映到终端；终端保存的新会话或删除也会同步到 GUI。归档、评论、草稿和界面状态继续保存在本机。原生占用锁保护同一会话，不能让 TUI 和 GUI 同时写入；同一会话也只允许一个 GUI 连接所有者。后台空闲连接释放后，监督服务约 10 秒回收 OMP 占用，删除及空会话清理可能因此稍晚完成。

远端同步先读取标题、路径和版本等轻量索引，仅为当前会话按需读取正文；已加载且版本未变时不重复传输历史。索引刷新保留本机已有正文、任务及子智能体缓存，新建／删除通道独立于历史加载。启动同步使用 Shimmer，失败后显示等待重试，成功后清除对应同步错误。

文件、变更、行内路径链接及子智能体历史在远端解析；标签页复用本地模式的编辑、高亮、查找和未保存确认。保存前核对内容版本和实际目标，使用同目录临时文件替换；冲突保留缓冲区。保存确认丢失时先查询操作记录，必要时核对同一目标的精确内容，无法确认则保留 dirty 状态。外部程序仍可能在检查和替换之间写入，因此这不是对任意外部写者的绝对原子 CAS。

文件变化通过远端监听通知，通知合并后刷新；另有低频重查弥补漏事件。断线会重建监听，未保存缓冲区不被刷新覆盖。设置页操作对应环境的 OMP 配置，模型、推理、服务、角色和子智能体表单均在该目标读取及保存。

从 Windows 拖入的普通附件先上传到远端会话缓存并校验摘要，模型得到远端路径；图片继续采用原生图片消息。删除 GUI 会话会清理对应附件缓存；归档保留缓存。本机凭据不会随附件自动上传。

## 断线、关闭与升级

运行中的远端 OMP 由私有监督进程持有，SSH 断开、切换环境或关闭 GUI 都不会代替“停止任务”。需要结束模型工作时，应在连接正常时点击停止。离线时保留编辑缓冲区，发送、停止和交互答复须等待连接恢复。

客户端以退避间隔自动重连。监督服务为会话事件编号并保留最多 8192 条／64 MiB 的内存记录；缺口、积压过大或进程代次变化时读取原生历史和当前状态，重新核对模型、任务及子智能体。不会重放提示词等有副作用的指令。变更操作先持久化受理记录，再执行并保存确认；无法确定结果时显示待确认，先检查历史或文件内容再决定下一步。

0.8.1 的 GUI／服务管理协议为 3，原生 OMP 协商仍为 2。管理响应按不超过 1 MiB 的物理帧传送，单次响应上限 256 MiB；超过上限返回错误并保留通道，索引仍可使用。管理请求及原生发送指令仍限制 64 MiB，原生接收逻辑消息上限 256 MiB。恢复时先等待原生协议协商和状态查询；空闲会话从日志按需恢复，运行中的会话查询当前消息。

重新打开 GUI 可附着到仍在运行的远端会话。无连接、无任务且不等待交互的 OMP 约 10 秒回收，监督进程没有会话约 5 分钟退出。新版本使用独立服务地址；升级前宜先结束旧版本任务，旧进程持有会话时，新版本会遵守占用保护。服务崩溃、Linux 重启或 OMP 退出后，不保证工具进程无缝继续；恢复原生历史并报告实际状态，不自动重跑。

## 数据位置与排查

| 内容 | 位置或处理方式 |
| --- | --- |
| GUI 环境、草稿和评论 | Windows GUI 数据目录，按环境及会话隔离 |
| OMP 配置／原生历史 | 所选 Linux profile 的 `omp config path` |
| 远端附件／操作确认 | `$XDG_DATA_HOME/omp-gui/`，未设置时为 `~/.local/share/omp-gui/` |
| 私有服务 socket | `/tmp/omp-gui-<uid>/`，仅当前用户访问；不向网络监听 |
| 安装构建诊断 | GUI 连接状态及错误信息，安装输出只保留有界尾部 |

操作确认记录只保留摘要与结果，不保存整份提示词／上传正文。每个记录作用域最多 10000 项，达到上限会拒绝新的变更，避免静默丢失去重保证；维护时不要直接删除未确认记录。附件和已安装版本不会按时间自动清除。

连接失败时先检查相同 Host 的终端 SSH、密钥／Agent、远端 OMP 路径覆盖和服务版本；首次源码构建失败时检查 Rust／Cargo 和依赖网络。文件采用 UTF-8，单文件预览最多 2 MB，项目最多枚举 5000 项；附件沿用每个 16 MiB、每次最多 16 个／合计 32 MiB。Linux 路径区分大小写并保留反斜线，不能填写 Windows 盘符路径。

实际联调使用 Linux x86_64、OMP 18.14.2；ARM64 已加入 CI 构建配置，尚未在真实 ARM 主机验证。故障验证范围见[验证说明](testing.md)，未对测试主机执行重启或破坏网络配置。
